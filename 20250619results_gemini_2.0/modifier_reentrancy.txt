**Revised Recommendation on Reentrancy Mitigation**

The initial fix suggestion, updating the balance before the `supportsToken()` call, is **incorrect** and would *not* prevent the reentrancy vulnerability. This is because the `supportsToken()` call allows the attacker to re-enter the *entire* `airDrop` function via their malicious `supportsToken()` implementation.  The vulnerable point is that the contract balance is checked in a modifier and the attacker controls what the `supportsToken` function of the calling contract returns and if that function calls back into the initial contract.

To correctly mitigate the reentrancy vulnerability in this specific scenario, the following approaches can be taken:

1.  **Modify the modifier `supportsToken`**: Remove the external call inside the `supportsToken` modifier to prevent calling an arbitrary contract.
2.  **Reentrancy Guard:** Use a reentrancy guard on the `airDrop` function if modifying the modifier is not desirable.

Let me provide an example using the Reentrancy Guard:

```solidity
pragma solidity ^0.4.24;

import "openzeppelin-solidity/contracts/utils/ReentrancyGuard.sol"; // or equivalent

contract ModifierEntrancy is ReentrancyGuard {
  mapping (address => uint) public tokenBalance;
  string constant name = "Nu Token";

  //If a contract has a zero balance and supports the token give them some token
  function airDrop() hasNoBalance supportsToken nonReentrant public{
    tokenBalance[msg.sender] += 20;
  }

  //Checks that the contract responds the way we want
  modifier supportsToken() {
    require(keccak256(abi.encodePacked("Nu Token")) == Bank(msg.sender).supportsToken());
    _;
  }
  //Checks that the caller has a zero balance
  modifier hasNoBalance {
      require(tokenBalance[msg.sender] == 0);
      _;
  }
}

contract Bank{
    function supportsToken() external pure returns(bytes32){
        return(keccak256(abi.encodePacked("Nu Token")));
    }
}

contract attack{ //An example of a contract that breaks the contract above.
    bool hasBeenCalled;
    function supportsToken() external returns(bytes32){
        if(!hasBeenCalled){
            hasBeenCalled = true;
            ModifierEntrancy(msg.sender).airDrop();
        }
        return(keccak256(abi.encodePacked("Nu Token")));
    }
    function call(address token) public{
        ModifierEntrancy(token).airDrop();
    }
}
```

**Explanation of Reentrancy Guard:**

The `ReentrancyGuard` from OpenZeppelin provides a simple mechanism to prevent reentrant calls to a function.  By inheriting from `ReentrancyGuard` and applying the `nonReentrant` modifier to the `airDrop` function, we ensure that the function cannot be called again before the first invocation completes. This breaks the attack vector in the `attack` contract.  The `supportsToken()` function is still making an external call but it is within the scope of `nonReentrant` so, `airDrop` will not be called again while it is already executing.

**Important Consideration:**  The core issue is the combination of the external call within the `supportsToken` *modifier* and the ability for an attacker to control the contract being called.  If it is not essential to call an arbitrary contract in the `supportsToken()` function, the best solution is to remove or restrict this external call.

**Recommendation Summary:**

1.  **Strongly Recommended:**  Remove or restrict the external call inside the `supportsToken` modifier if possible.
2.  **Alternative (If External Call is Required):** Use a reentrancy guard on the `airDrop` function.
3.  **Use SafeMath:** Always use SafeMath for arithmetic operations to prevent overflows/underflows.
